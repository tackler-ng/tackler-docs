=== Synchronizing Journals

Transaction data ("journals") are synchronized to the HQ's main journal with git merge. Journals are separated, and they are not normal clones of each others, so the merge must be done with unrelated histories (`--allow-unrelated-histories`).

Tackler supports storing single transactions into xref:journal:index.adoc#journal-files[single files], and it also has support for xref:journal:sharding.adoc[journal data sharding]. Both of these features are utilized, so that there won't be merge conflicts when these unrelated data streams are merged.

=== Tackler configuration

This is pretty standard configuration for tackler.  Most notable, the strict mode is turned on, so that all  accounts, commodities and tags must be defined. This prevents unknown accounting data to be used by stores, and ensures that HQ has full visibility to the used Chart of Accounts.

There is no need to define store journals at HQ level, as tackler xref:reference:tackler-toml.adoc#kernel-input-git[automatically discovers transactions] in defined journal.

The xref:auditing:index.adoc[audit mode] is also activated, which means that tackler calculates checksums of used journal data.  With xref:journal:git-storage.adoc[Git Journal Backend] this provides cryptographic proof of used journal data.

The journal setup is configured so that it's possible to switch between working copy journal (plain filesystem) and Git backend with `--input.storage "fs"` xref:reference:command-line.adoc#input-storage[command line argument].
