== Intro

High-Low Security setups are systems where the system is partitioned into multiple different security zones. Typically, data transfer, visibility and availability is restricted between these zones.  For example, data can flow from lower environments to the High Security Zone, but not vice versa.

Traditional Plaintext Accounting example would be a setup where groceries are recorded and processed with mobile phone, but whole financial data, including medical bills and investment portfolio information is processed in more secure computer setup.  If the phone gets mugged and thugs manage to open it, they are only wiser about your spending habits about ice cream and candies.

This example shows how this kind of High-Low Security Accounting setup can be defined and how data synchronization could be implemented with PTA tool. The example is tackler specific, but the core concept of it can be adapted to other PTA tools.


== Demonstrated Concepts

This example demonstrates many advanced concepts of tackler, and it's also utilizing advanced features of Git Storage backend.  Some of these are:


* Many features of xref:journal:git-storage.adoc[Git Storage] based journals, including automatic data synchronization between High and Low zones, and point-in-time snapshots of journal
* xref:auditing:index.adoc[] and validating used journal data
* xref:usage:txn-filters.adoc[Filtering] journal based on transaction tags
